# حالة الحزمة — قبل النشر

## تم في هذه الحزمة
- دمج أساس React/Vite مع الهوية والموارد من نسخة PWA الأخيرة.
- إزالة بيانات العرض التجريبية وlocalStorage من واجهة الإنتاج.
- إضافة تسجيل دخول Supabase وإنشاء حساب مدرب مع انتظار الموافقة.
- إضافة واجهات مربوطة بالجداول: الطلاب، الحضور، الاختبارات، النتائج، الحصص، كراس المدرب الخاص، الفريق، سجل التعديلات، وإعدادات المؤسسة.
- جعل الكراس يستعلم من `coach_notebook` حسب `owner_id`.
- إضافة ربط إصدار BARÈME بالنتائج عبر عمود `scale_version_id` في migration إضافي.
- إضافة جداول ومشغلات تنبيه التأهيل وسجل تاريخه، إضافة إلى جداول المرافق والمعدات.
- إضافة إعدادات Vite وCloudflare Workers Static Assets وPWA.
- لا توجد واجهة لتوليد البرامج التدريبية، ولا توجد صفحة قياسات جسم.

## ما لم يمكن إثباته في بيئة البناء الحالية
- تعذّر تنزيل npm dependencies في بيئة العمل بسبب انتهاء مهلة الاتصال بمستودع npm؛ لذلك لم يتم تنفيذ `npm run build` ولم يتم إنشاء `dist` هنا.
- لم تتوفر جلسة إدارة مباشرة لمشروع Supabase لإجراء introspection على المخطط المنشور أو تجربة RLS بحسابات فعلية.
- لم يتم النشر إلى GitHub أو Cloudflare من هذه الحزمة.

## قبل اعتبارها Production
1. شغّل `npm install` ثم `npm run build` في بيئة متصلة بالإنترنت. يجب أن ينجح البناء دون أخطاء.
2. راجع ملف migration الإضافي مقابل الجداول والدوال والسياسات الموجودة فعلًا في Supabase. لا تنفّذ ملفي المرجع التأسيسي.
3. اختبر بحساب مالك المنصة، حساب إدارة المؤسسة، وحسابي مدربين مختلفين: يجب أن يفشل أي وصول إلى دفتر مدرب آخر حتى لو جرى استدعاء Supabase مباشرة.
4. اختبر موافقات الحسابات، استيراد التلاميذ، تسجيل حضور متكرر في نفس الحصة، BARÈME بتاريخ قديم، والتنبيه بعد خمس غيابات متتالية ثم انقضائه بعد حصتين فعليتين.
5. لا تدخل بيانات تلاميذ حقيقية قبل نجاح الاختبارات أعلاه.
