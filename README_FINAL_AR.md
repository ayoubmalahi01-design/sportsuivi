# Sport Performance — نسخة موحّدة مرشّحة للإنتاج

هذه الحزمة مبنية على أحدث مصدر محفوظ `Sport-Performance-REPORTS-1.3.1.zip`، مع دمج إصلاحات وتطويرات إضافية في نسخة واحدة.

## استقلال التطبيق

Sport Performance هو مكان العمل اليومي المستقل: الإدارة والمدربون يضيفون التلاميذ والنتائج والوزن والحضور والحصص والمرفقات والتقارير من داخل التطبيق نفسه. لا توجد حاجة للرجوع إلى Supervise أو بوابة خارجية لإدخال معلومات التلاميذ أو استرجاعها. Supabase هنا خلفية تقنية لتخزين البيانات والمصادقة فقط؛ لا يحتاج المدرب أو الإداري إلى فتح لوحة Supabase.

## ما أُنجز في هذه الحزمة

- إزالة صفحة سجل التعديلات من الواجهة وعدم تحميل `audit_log` للمستخدمين. ملف الترقية يوقف Triggers التدقيق المستقبلية ويحجب قراءة السجل عن `authenticated`، مع **الإبقاء على السجلات التاريخية دون حذف**.
- فصل قائمة التلاميذ حسب السنة الدراسية عبر `school_year_id`؛ عند بدء سنة جديدة تُؤرشف السنة السابقة وتلاميذها وتبقى للقراءة فقط، وتبدأ السنة الجديدة بقائمة مستقلة. أرقام التلاميذ يمكن أن تتكرر بين السنوات.
- حماية الكتابة إلى سنوات مؤرشفة من جهة قاعدة البيانات، وليس من الواجهة فقط.
- رفع برنامج الحصص ومحتواها كتابةً أو كمرفق PDF / Word / Excel / TXT، ليشاهده المدرب ويختاره عند بدء الحصة.
- إضافة حقل صورة للتلميذ ورفع الصور إلى Storage خاص، وعرضها داخل ملفه الرياضي.
- رفع حد تحميل القوائم مع pagination، وتقسيم عمليات الحضور والاستيراد إلى دفعات 500 سجل حتى لا تتوقف عند 50 أو 1000 تلميذ.
- إصلاح ربط الجنس بين واجهة الاختيار وقيم قاعدة البيانات `M/F`.
- إصلاح مشكلة الحصة المفتوحة الوهمية: البحث عن حصة غير منتهية يقتصر على حصة اليوم والسنة المختارة؛ الحصص القديمة تظهر كغير منتهية من يوم سابق ولا تمنع بدء حصة اليوم.
- إصلاح معالجة تنبيه التأهيل عبر RPC `handle_rehab_notification` بدل UPDATE مباشر لا تسمح به الصلاحيات الحالية.
- توسيع حساب Navette لإظهار السرعة km/h وm/s والمسافة التراكمية بالكيلومتر والمتر بحسب palier. Pompes وAbdos يعرضان التكرارات/الدقيقة والتكرارات/الثانية ومتوسط زمن التكرار على أساس 60 ثانية.
- إضافة اختيار اللغة العربية / الفرنسية / الإنجليزية واتجاه RTL/LTR، مع قاموس للواجهة الأساسية.
- تحسين PWA وملف manifest وService Worker وأيقونات التثبيت على الهاتف والحاسوب.
- إزالة عنوان Supabase ومفتاح المشروع السابقين من المصدر؛ الإعداد صار عبر متغيرات البيئة.

## ما يجب تنفيذه قبل التشغيل

### 1) ربط Supabase الصحيح

في إعدادات Cloudflare Build أو ملف `.env.production` المحلي، عيّن:

```env
VITE_SUPABASE_URL=https://xbjthetphqxdhwufkmly.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_SUPABASE_PUBLISHABLE_KEY
```

استخدم مشروع Sport Performance الصحيح الذي يحتوي بياناتك. لا تستخدم `service_role` أو كلمة مرور قاعدة البيانات في المتصفح.

### 2) ترقية قاعدة البيانات

الملف الوحيد المخصص للترقية الجديدة هو:

`supabase/migrations/20261112_production_upgrade.sql`

اقرأه كاملًا قبل التنفيذ. يجب أن تكون جداول `institutions`, `profiles`, `students`, `classes`, `school_years`, `sessions`, `attendance`, `test_results`, `body_measurements`, `student_measurements`, `observations`, `audit_log` موجودة كما في المخطط الحالي الذي راجعناه. الترقية تضيف أعمدة وجداول وسياسات وTriggers وRPC وStorage؛ لا تحذف بيانات التلاميذ أو النتائج أو القياسات أو سجلات التدقيق القديمة.

**لا تشغّل** ملفات `docs/legacy/20261109_production_additions_REVIEW_ONLY.sql` أو ملفات `*_DO_NOT_RUN.sql` أو `legacy-schema-reference-do-not-run.sql` على قاعدة البيانات الحالية. هذه مراجع قديمة وليست ترقية متوافقة مع مخطط اليوم.

بعد SQL، نفّذ استعلامات التحقق الموجودة في نهاية ملف الترقية، ثم اختبر إنشاء سنة جديدة بحساب إداري تجريبي قبل استعمالها على بيانات حقيقية.

### 3) تثبيت التطبيق وبناؤه

يتطلب Node.js 20 أو أحدث:

```bash
npm install
npm run build
```

ينتج مجلد `dist/`. للنشر على Cloudflare Workers Static Assets:

```bash
npx wrangler deploy
```

تأكد من أن اسم Worker في `wrangler.jsonc` يطابق مشروع Cloudflare الذي تريد تحديثه، وأن متغيرات Vite أُضيفت في إعدادات البناء قبل إنشاء `dist`.

## تثبيت التطبيق على الهاتف والحاسوب

هذه الحزمة PWA قابلة للتثبيت من المتصفح وليست APK أو تطبيقًا منشورًا في Google Play/App Store:

- Android: افتح رابط HTTPS في Chrome ثم اختر «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية».
- iPhone/iPad: افتح الرابط في Safari ثم مشاركة ← إضافة إلى الشاشة الرئيسية.
- Desktop: Chrome أو Edge يعرضان خيار Install بجانب شريط العنوان أو من قائمة المتصفح.

يلزم نشر HTTPS ونجاح manifest وService Worker حتى يظهر خيار التثبيت. لا يمكن إنشاء APK موقّع أو نشر متجر من هذه الحزمة وحدها.

## ملاحظات وحدود التحقق

- ملفات SQL لم تُنفذ على قاعدة Supabase من هذه بيئة العمل.
- تعذّر تثبيت حزم npm هنا بسبب انتهاء الاتصال بمستودع npm وعدم وجود الحزم في cache؛ لذلك لم أستطع تنفيذ `npm run build` أو تأكيد `dist`.
- تم التحقق من تركيب ملفات JavaScript/JSX بواسطة TypeScript transpiler دون أخطاء تركيب.
- الترجمة الحالية تغطي معظم النصوص الثابتة الأساسية، لكنها تحتاج اختبارًا بصريًا واستكمال أي نصوص ديناميكية أو رسائل لم تدخل القاموس.
- لم يتم نشر الحزمة إلى Cloudflare من هنا؛ النشر يتطلب صلاحية حسابك وإعدادات Worker.
- تدفق تسجيل المستخدمين متعدد المؤسسات (`handle_new_user`) ما زال يحتاج مراجعة مستقلة قبل فتح التسجيل العام؛ لا تعتبر موافقات المنصة/المؤسسة مكتملة لمجرد وجود شاشة الفريق.
- بروتوكول Navette يعتمد عدد أشواط كل palier كما في جدول التحويل داخل الكود؛ راجعه مقابل البروتوكول الرسمي المعتمد في مؤسستك قبل اعتماد التقارير.

هذه الحزمة مرشّح موحّد للعمل والاختبار، وليست إعلانًا بأن كل اختبارات الإنتاج أو الربط السحابي قد نجحت.
